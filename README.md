# INTELCODE

> **"Understand your codebase. Not just your files."**

IntelCode is an enterprise-grade developer intelligence platform that transforms raw source code repositories, Git history, pull requests, issues, and documentation into a searchable, interactive engineering knowledge layer. Developers can authenticate via Supabase Auth, connect GitHub repositories, extract AST-aware symbol chunks, and conduct natural-language codebase investigations strictly grounded in retrieved source context with clickable line-level citations.

---

## 1. Overview & Key Capabilities

- **Code-Centric Developer UI:** Built with the restraint and precision of Linear and modern IDEs. Dark theme by default, restrained developer palette, JetBrains Mono code typography, and zero generic AI bloat.
- **Monaco Code Intelligence Viewer:** Embedded read-only Monaco editor with syntax highlighting, line navigation, and automated line-range highlighting on source citation click.
- **Voyage Code 4 Embeddings (512-d):** High-precision code vector representations generated by Voyage AI's specialized `voyage-code-4` embedding model at 512 dimensions with strict query/document asymmetry (`input_type: "document"` for repository code chunks, `input_type: "query"` for user search questions).
- **Hardened Resumable Indexing Pipeline:**
  - **Git Blob SHA Differential Engine:** Compares Git tree blob SHAs with database records; unchanged files take 0ms to index, while only modified and newly added files are downloaded, chunked, and embedded.
  - **Non-Destructive Staging & Atomic Cutover:** Existing chunks and embeddings remain fully queryable while an indexing pass runs. Obsolete chunks are pruned only after replacement vectors are verified, eliminating search downtime and data loss during failed jobs.
  - **AST-Aware Code Chunking:** Extracts language-aware symbols (functions, classes, methods, interfaces, types) with exact line boundaries (`start_line`, `end_line`) across TypeScript, JavaScript, Python, Go, Java, and C++, with deterministic bounded fallback chunking.
  - **Content Deduplication (SHA-256):** Every code chunk is fingerprinted with a SHA-256 hash across repository ID, relative file path, chunking version, and content.
  - **Zero-Secret Ingestion Defense:** Ingestion regex filters reject `.env*`, `.pem`, `.key`, `id_rsa`, `credentials.json`, binary executables, and build artifacts before indexing or RAG generation.
  - **Multi-Batch Continuation & Durable Checkpoints:** Long-running indexing jobs checkpoint progress durably into `public.indexing_jobs` with resumable continuation tokens (`cursor`, `batchLimit`), respecting Vercel serverless execution limits.
- **Hybrid Retrieval & Grounded RAG:**
  - Combines **pgvector** cosine similarity (512-d HNSW index) with PostgreSQL Full-Text Search rank via Reciprocal Rank Fusion (RRF).
  - Answers generated exclusively by Google Gemini (`gemini-2.5-flash` / `gemini-3.8-flash`) using retrieved code chunks. The AI is forbidden from fabricating code, files, or citations not present in retrieved context.
- **Interactive Source Citations:** Every answer includes verified citations linking to repository file paths, line ranges, and commit SHAs with deep editor navigation.

## 2. Technology Stack

- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS, Monaco Editor (`@monaco-editor/react`), React Router v6, TanStack Query, Lucide Icons, `react-markdown` with `remark-gfm`.
- **Backend & Serverless Runtime:** Vercel Serverless Functions (Node.js 20+ runtime, TypeScript) located in the root `api/` directory with clean modular business logic in `src/server/`.
- **Database & Vector Search:** Supabase PostgreSQL with `pgvector` extension, HNSW vector indexes, and Row Level Security (RLS) on all tables.
- **Embeddings Provider:** Voyage AI `voyage-code-4` (512 dimensions, floating-point vectors, batching with exponential backoff and jitter).
- **Reasoning & Answer Generation:** Google Gemini API (`gemini-2.5-flash` / `gemini-3.8-flash`), accessed exclusively via serverless endpoints.
- **Repository Integration:** GitHub REST API & Git Data API (trees, blobs, commits, issues, pull requests).
- **Testing:** Vitest, Testing Library, jsdom (126 unit and integration tests across 9 suites).

## 6. Supabase Configuration & Migration Steps

### Initial Setup
1. In your Supabase Dashboard, navigate to **Database > Extensions** and enable `vector`.
2. Open the **SQL Editor**.

### Executing Migrations in Order:
1. **Base Schema & RLS Policies:**
   Run `supabase/migrations/20250101000000_init_intelcode.sql`.
   This creates `repositories`, `files`, `chunks`, `indexing_jobs`, `github_connections`, commit/PR/issue tables, and baseline RLS policies.

2. **Voyage Code 4 (512-d) Vector Migration:**
   Run `supabase/migrations/20261017000000_voyage_code_4_embeddings.sql`.
   This migration:
   - Adds `embedding_v4 vector(512)` to `public.chunks` and `public.documents` alongside existing vectors (preserving existing data without breaking legacy 768-d tables).
   - Adds metadata tracking columns: `embedding_model`, `embedding_dimension`, `chunk_hash`, and checkpointing progress fields.
   - Builds HNSW vector indexes: `idx_chunks_embedding_v4 USING hnsw (embedding_v4 vector_cosine_ops)`.
   - Creates `idx_chunks_chunk_hash` for fast chunk deduplication.
   - Defines the overloaded `hybrid_search_chunks(..., query_embedding vector(512), ...)` and `hybrid_search_chunks_v4` SQL functions with reciprocal rank fusion and mandatory tenant access enforcement (`has_repo_access`).

### Rollback Procedure
If you ever need to roll back the 512-dimensional Voyage vector schema to the original state:
Run `supabase/rollback/20261017000000_voyage_code_4_rollback.sql`.
This cleanly drops the 512-d functions, HNSW indexes, and new columns while keeping your base schema intact.

## 7. Voyage Code 4 Setup & Embedding Specifications

IntelCode uses Voyage AI's latest code embedding model, `voyage-code-4`:
- **Endpoint:** `https://api.voyageai.com/v1/embeddings`
- **Model:** `voyage-code-4`
- **Output Dimension:** `512`
- **Input Asymmetry:**
  - Code chunks from files: `input_type: "document"`
  - Natural language search queries: `input_type: "query"`
- **Truncation Policy:** `truncation: false`. Code is split into AST-aware chunks within token bounds rather than silently truncated by the model.
- **Error Handling & Resilience:**
  - Exponential backoff with random jitter on HTTP 429/500/502/503/504 errors.
  - Respects HTTP `Retry-After` header.
  - Fails fast (without aggressive retries) on 401 Unauthorized, 403 Forbidden, or quota errors.
  - Strict vector validation: verifies that every returned vector contains exactly 512 finite floating-point numbers.

## 8. GitHub Authentication: Two Distinct OAuth Flows

IntelCode supports two distinct GitHub OAuth flows. Do not mix their redirect callbacks:

1. **Supabase Social Login (User Authentication):**
   - Managed automatically by Supabase Auth (`supabase.auth.signInWithOAuth({ provider: 'github' })`).
   - Callback URL configured in your Supabase Dashboard: `https://<supabase-project-id>.supabase.co/auth/v1/callback`.
   - Purpose: Authenticates the user into IntelCode and creates their profile.

2. **IntelCode GitHub App Connection (Repository Ingestion & Git Access):**
   - Managed by IntelCode's serverless OAuth route (`/api/github?action=exchange`).
   - Callback URL registered in your GitHub Developer Settings:
     - Local: `http://localhost:5173/auth/callback` or `http://localhost:5173/api/github`
     - Production: `https://your-intelcode-deployment.vercel.app/auth/callback`
   - Purpose: Obtains an authorized GitHub access token stored encrypted in `github_connections` for reading repository trees, Git blobs, commit history, and pull requests.

## 9. Google Gemini Configuration

Google Gemini is used exclusively for codebase reasoning, question answering, and impact analysis:
- **Model:** Configurable via `GEMINI_MODEL` (`gemini-2.5-flash` recommended for low latency; `gemini-3.8-flash` for high-depth reasoning).
- **Grounded Answering:** Prompts are structured with retrieved source code chunks including repository name, relative path, line ranges, and Git SHA.
- **Anti-Hallucination Guardrails:** If the retrieved evidence does not contain the answer, the model explicitly states that the codebase does not provide sufficient context rather than guessing.

## 12. Repository Indexing, Checkpointing & Recovery

Large codebases are indexed across safe, bounded serverless invocations:

1. **Job Initialization:** When indexing starts, a job record is created in `public.indexing_jobs` with status `fetching`.
2. **Tree Analysis & Differential SHA:** The Git tree is compared against existing indexed files in PostgreSQL. Only new or modified files are downloaded.
3. **Chunking & Embedding in Slices:** Files are processed in bounded batches (`batchLimit: 50`). If more files remain, the response returns `has_more: true` and `next_cursor: "<last_file_path>"`.
4. **Resumable Client Polling:** The frontend automatically issues continuation requests with `cursor` until all files are processed.
5. **Atomic Commit & Pruning:** Deleted files and obsolete chunks are pruned only during the final batch pass after all new chunks are verified.

### Recovering & Retrying Failed Jobs
- **Transient Failures (Rate Limits / Network):** The UI displays a **Retry** button. Resuming an indexing job uses the cached Git tree and skips all files that already have verified chunks in the database.
- **Daily Quota Pauses:** If Voyage or Gemini quotas are exceeded, the job transitions to `paused` with a clear explanation. Once the quota window resets, clicking **Retry** resumes immediately from the checkpoint.
